## 3. 并入 V1 首折前的有限修正

### 3.1 必修：验收不能在缺测时通过

`src/qf3/s5_v0_acceptance.py` 的 `compare()` 只遍历传入用例，以 `failures == 0` 判通过，没有验证必需场景集合。主 Agent 实际复现：

- `compare({}, {})` 返回 `cases={}`、`tolerance_failures=0`、`passed=True`。
- 只传入 `real_20190603`，也返回 `passed=True`。

当前默认构造器确实产生九个场景，故这不推翻已经复算的九场景数值；但报告“缺 case 会失败”是错误完成声明。这类**未测也能通过**的问题不能带入年度包验收。

执行要求：

1. 正式验收入口声明必需场景集合并检查完整覆盖，拒绝空集、缺项及意外替换；若保留单场景调试接口，其结果不得标成完整验收通过。
2. 每个场景断言非空、预期输入形状；逐层先断言实际与参考 shape 完全一致，再计算误差，禁止 NumPy 广播把 shape 错误掩盖成数值通过。
3. 将必需的有限性、覆盖、形状和秩检查纳入总判定，不能只写进 JSON 不影响通过状态。当前真实日期/小池秩一致要求保留；未来年度近 tie 如需专门容差，按任务书先定义与记录，不能遇到失败后静默忽略。
4. 用有限负向样例验证：空集、缺一个场景、错误 shape、非有限输出、超容差输出均不能得到完整通过。用例不是为了增加数量，而是覆盖现有验收器的可复现漏洞。

实现后保存新验收结果及代码身份，明确取代旧结果的哪一项判定；不得覆盖旧数据来冒充当时就已具备负向校验。无需重新训练或导出同一套旧权重。

### 3.2 溯源和加载边界

- 当前 `design` 哈希只覆盖预处理配置，不等于预处理实现代码哈希。V1 验收记录还应覆盖验收脚本、实际预处理代码、模型配置、参考前向代码，以及输入夹具/面板的可核验身份；记录准确命令、环境和线程配置。
- 静态加载器对 `k`、输入宽度、隐藏宽度等要求严格正整数，并以负向样例证明零维度等错误会拒绝。不重新设计已经验证正确的前向。
- manifest 仍处于草案阶段，允许作为 V0 产物接收；V1 必须由机器检查实际文件和成员，不能把文字 `hard_rules` 当作已执行校验。沿用上次审查规定的缺成员、重复 seed、错 hash、错特征顺序、非法权重、额外家族 rank 等负向检查。
