## 1. 目标与范围

在已完成数据审计和最小交付链路的基础上，交付一套本地可复现的比较体系、轻量基线、强基线候选，以及可由用户手动上传的 CPU 提交包。阶段内完成必要的真实组合回测，不把 IR 留到后期。

执行 Agent 负责全部实现。优先复用其已经打通的接口和合规封装，记录来源与版本；本工作区尚未看到这些实现，不可把其他目录的报告当作本项目已验收产物。不操作上传，不占用官方提交额度做链路测试。

不重新开展全面数据审计；仅对新实现做标签、时间、连接、特征和输出一致性检查。不在本阶段进行大规模特征挖掘、全模型族比赛或大网格搜索。

## 2. 规则落地与回测契约

阅读 PROJECT_PLAN.md 所列官方材料并登记以下固定约束：

- 仅官方 2016–2022 数据；每日当期股票池由 Barra 定义；PIT；模型行情输入最多 120 个交易日。
- 标签 H=1：信号 t 收盘后，Open(t+2)/Open(t+1)-1；训练截止按标签结束时点处理，无合法标签的尾部样本不伪造标签。
- 用户禁用名称和 is_st：模型特征、衍生特征、名称解析和持久化填补参数均不得携带其信息。不改写原始数据。
- 三张推理表以外的训练目录附加数据不得成为隐藏推理不可获得的必需特征。行业/权重可供合法本地回测用途，不硬编码未来行业。
- 预测返回三列、完整合法股票池、停牌股也给分、无重复或非有限分数；Python 3.11、CPU、自包含、固化学习参数。
- 提交包 < 1024 MB，并记录实际字节数、压缩包及解压目录大小，保留余量。

本地平台部署 skd-backtest，固定 commit/版本。明确 daily rebalance=1、holding_period=1、lookback<=120；不要沿用示例的 5/5/252。

正式组合参数未知时，建立一个固定、有出处/假设标识的 Barra 参考配置。SHARE 参数仅作参考，不能当官方参数。报告价格/标签、交易费用、约束、起止日期、warm-up 和账户连续性。

is_st 不进入预测已确定；交易引擎对该列的需求是独立问题。先保留原始数据和平台实现，不通过删除原始列或修改引擎掩盖问题。如为分析采用置零视图，必须另列配置与假设，不能声称正式执行也是置零；发现影响结论时在报告中提请主 Agent 审查。

## 3. 环境

- 建立本地 Python 3.11 环境，锁定必需依赖、平台版本和复现入口；无需一次安装全部潜在研究库。
- 先确保 CPU 路径。GPU 探针可由执行 Agent 运行并记录，确认可用再加速；不可将 GPU 修复变为首阶段前置长任务。
- 控制内存、线程与并发，初期不同时启动多个全量面板重任务；先量测一次代表性训练和回测耗时。
- 固定随机性；如 GPU 带来非确定性，说明预期误差和验证办法。CPU 推理必须显式测试，不能仅凭库文档认定可用。

## 4. 基线与强基线方案

轻量对照 B0：正则化线性模型（默认 Ridge），使用合法官方因子/Barra 和一致截面预处理，目标为当日 H=1 收益的截面秩。学习得到的填补/缩放参数只在训练期拟合并固化；当日截面统计与训练期拟合参数明确分开。

强基线候选 S1：LightGBM 截面秩标签回归；先用合法官方因子和 Barra，再比较一个小型、提前定义的量价衍生特征组。优先考察叶数/深度、叶节点样本量、正则、采样、学习率与轮数的合理组合。

强基线候选 S2：CatBoost 同标签、同样本和可比特征的有限对照，检查模型形式是否提供增量；不能因 SHARE 的历史成绩直接指定其获胜。

建议先执行少量基准配置，依据首批耗时将 LightGBM 首轮范围控制在约 8–12 个有区分度配置、CatBoost 约 2–4 个；这是可调整的首轮预算，不是要求凑满实验。只将少数领先/互补候选推进时间确认和完整回测。若 CatBoost 安装/运行异常，不阻塞 LightGBM 基线，记录缺失对照与原因。

派生特征只选小组，例如多窗口收益/波动、量额相对历史水平、隔夜/日内分解。每项写出公式和底层所需交易日数；如命名“120 日收益”实际需要 121 个价格点则不允许。对源表已提供且用户确认可用的因子直接按当前合同使用，不以重新构造它们为前置任务。

基线阶段不要求复杂融合。可对已保存的两个候选预测做一个预先声明的简单秩平均对照，只有结果支持才保留；不得自动把后验最优融合当独立验证。

## 5. 验证与效率

默认安排：2019 和 2020 为开发窗口，各自的模型只用该年之前已实现标签的样本训练。配方冻结后，以此前合法数据重训并预测 2021 作为时间确认。2022 留给后续确认，首阶段不用于日常调参。

- 早停在训练区间内部的末端子窗口完成，固定轮数后可重训该折训练数据；不要用确认年反复早停再宣称独立确认。
- 所有模型采用相同日期/代码和合法标签集合。若不同模型因特征历史导致样本资格差异，必须对齐比较或单独说明。
- 输出逐年和汇总每日 RankIC，按日汇总，不用所有股票日混在一起算一个相关系数。
- 2019/2020 的配置选择后成绩属于开发结果，2021 只具有本轮冻结配方后的确认意义；由于参考材料已经披露旧研究，不能称任何一年为整个项目未知的盲测。
- 对基础模型和主要候选执行相同参考配置的真实组合回测，至少覆盖确认区间；粗筛候选不全部回测。清楚区分年度重置账户与连续回放。
- 报告组合 IR、净年化超额、跟踪误差、换手、回撤，必要时针对主要差异补充一个成本对照。不得用零成本结果冒充净收益。
- 候选差异很小时，才追加少量匹配种子或配对时间块分析，不默认所有配置多种子训练。

## 6. 候选训练与 CPU 包验收

第一阶段选型完成后，默认用全部官方合法有标签数据训练候选提交模型，使用已冻结配方和训练轮数；具体选择登记在训练配置中。不要把研究折模型不加说明地拿来提交，也不要把全量模型在训练历史上的回放称为样本外能力。

继续使用已经打通的提交结构，包含 inference.py、train.py、requirements.txt 和 model/。只验证新模型带来的差异：

1. CPU 上加载和预测，不依赖 CUDA、联网、包外数据或环境变量。
2. 离线特征与真实 as-of 切片经过 predict 得到的特征/得分相符；短历史、成分变化、缺失与停牌仍有完整输出。
3. 禁用字段从任意值改成其他值、或从模型研究输入移除，不应改变分数；测试仅在合适的本地推理输入副本上进行，不改市场原始数据或引擎交易字段。
4. 训练和推理使用同一特征定义/顺序，模型/预处理/融合参数完整固化，种子和依赖有记录。
5. 给出 CPU 推理耗时、峰值内存、模型及包大小；不知道官方具体时限时不能写“已满足官方时限”。
6. 输出可复现入口与运行证据，确认最终 train.py 能重建提交产物；正常随机差异须解释，不能只附一份从未执行的训练脚本。

不重新建立一个为公榜调试而用的空模型，不上传验证包。
