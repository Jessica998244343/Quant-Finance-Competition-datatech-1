## 三、尚未完成的问题，按影响排序

### 1. 同一个机器结果给出互相冲突的冻结身份

`v2_rev1_tcn_family.json` 第 141–146 行写 `frozen_alpha=0.25`，但紧随其后的 `dev_merged_at_frozen=0.001995571657577357`、`conf21_at_frozen_tcn=-0.0008136760019790135`、`both_dev_nonneg_at_frozen=false` 实际属于 α=0.50；第 181 行后的 `frozen_alpha_values` 才对应 α=0.25，文件同时声称 `passed_gate=true`。

这是实际交付错误，不是格式问题。依赖不同字段的下一步程序会得出相反结论。但 α=0.25 的原子复算成立，不能因汇总错误否认其真实增量。应从单一结构自动生成结果与报告，不能继续手改若干字段“修好表面”。还要区分研究初筛 +0.0005 与 V2 候选目标 +0.001。

### 2. TCN 正式入口无法正常完成 DEV 汇总

`src/qf3/s6_v2_tcn.py:402` 遍历 `WINDOWS`，其包含 DEV19、DEV20、CONF21，却传入长度为二的 `[244,243]`。

- 默认只运行 DEV19/DEV20 时，汇总访问不存在的 CONF21，将报错。
- 即使运行三年，三项数据与两项权重也不匹配。

这不自动否定已经保存的权重和预测，但说明交付源码尚不能按公开入口复现汇总。必须保存真正生成三 seed 家族、候选选择与冻结清单的程序/命令；临时交互计算的最终 JSON 不能代替可复现入口。

### 3. 新候选的规定验证没有做齐

原任务书 §8.2、§13.2–13.3 要求入围配方的半年训练起点验证、最终组合删除消融、逐日 ΔIC 和新组合配对区间。当前半年产物仅覆盖原控制，新报告未交付 TCN 对应起点实验；修好的 `v1_anchor_compare_rev1.json` 仍是 V1 的区间，不能转挂 TCN。

本次主 Agent 补算的区间可供核对，执行 Agent 仍须保存对应可重算产物。最终组合需检查删除 C1、TabM、TCN 后的效果，而非只证明加入 TCN 优于父组合。时间置乱主要是单 seed 诊断，静态控制也并非每年都差于 TCN；“说明增益来自有序时间支路”应改成“提供时间支路可能有用的对照证据，尚不能证明跨年稳定作用”。

### 4. 冻结清单未冻结全部决定预测的参数，2022 决策缺少直接增量参照

TCN 清单记录权重和 manifest 的哈希，但 manifest 内只绑定模型/预测，**没有绑定 `preprocessing.json`**。TabM 冻结也未绑定 `design_seed*.json`。因此改变 median/IQR、通道统计仍可通过现有冻结核验。还缺有序特征清单、训练/特征/融合/推理代码与配置的明确绑定。

新清单将主要 ΔIC 定义为候选−TREE，未要求新增 TCN 相对其直接父组合 V1 的增量。于是 TCN 即便弱于 V1，只要强于 TREE 仍会得到“支持”。这是主 Agent 需要在打开 2022 前补严的**决策口径**，不能全部归咎于执行 Agent：上轮要求明确 TREE 等参照，但未替它写完整的多级采用规则。下文给出规则，禁止看完 2022 再改。

### 5. 台账和产物仍被过度声明为齐全

- `v2_budget_ledger.json` 仍写“近期分支未触发、无新候选、11 配方、最终向量 0”，与本轮实际相反。TabM504 本身新增一个配方，至少须在旧 11 的基础上记入；其它复用/修正版/ResMLP按身份逐条核对，不能凭感觉报总数。
- TCN 五个 α 已用于最终候选选择，不能声称联合融合向量使用量为 0。区分成员初筛与最终融合用途，登记全部尝试，完整向量按规范化身份去重；不得借分类隐藏实际选型次数。
- `tabm_recent504_20261005__DEV19/DEV20` 各只有预测与 manifest，没有模型、预处理、训练曲线。它们只能支持“保存预测可复算”，不能支持“训练全产物可复现”。**本次不要求为已淘汰的 504 分支专门重训**：如实标为产物缺失、不得用于部署或晋级；修好保存逻辑以后新运行必须齐备。如以后重新启用此配方，才先补合法复训与完整产物。

### 6. 公共融合验证还可静默接受错误

本次内存负例证明：`family_q` 对某 seed 缺一行时内连接静默从三行缩为两行；输入 Inf 时可被排名转成有限值；`fuse` 接受 NaN 权重并输出全 NaN。`q` 列存在也不等于证明输入属于正确家族阶段，文档所称“不能混入最终排名”过强。

真实候选的池完整性已单独通过，所以不因此推翻本次 IC；但后续部署不能依赖恰好正确的输入。修复应限于显式契约和会失败的检查，不扩成无关框架开发。
