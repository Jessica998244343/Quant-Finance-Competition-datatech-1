# 提交失败诊断（evaluation failed with exit code 1）

日期：2026-10-05。**我没有拿到评测机日志**，以下按官方提交指南逐条核对并做可复现的本地验证，
区分"已确证的本地缺陷"与"最可能的原因"。

## 1. 官方文档的相关要求（Submission_Rules.pdf）

- 第 8 页：「评测环境使用 **Python 3.11**；Python 依赖**以参赛者提交的 requirements.txt 为准**；
  评测环境会**根据该文件预装相应依赖**；评测期间**禁止联网**。」
- 第 10 页：「`train.py` 无法正常运行」→ 视为**训练不可复现**（取消资格级）。
- 第 5 页：输出必须恰好 `date, code, score`，`date` 为 `YYYY-MM-DD` 字符串，
  覆盖当日完整合法池、无重复、无 NaN/Inf。
- 第 9–10 页：禁止动态执行、修改 `sys.modules`、子进程、包外读取。

`exit code 1` 属于**进程级异常退出**，最可能发生在「装依赖」或「导入 inference.py」阶段，
而不是输出格式被判错（那类问题通常报格式错误而不是退出码 1）。

## 2. 已确证的本地缺陷（FINAL_v1）

**我的 `requirements.txt` 声明了我没有验证过的 torch 制品。**

| 项目 | 声明/使用 | 实测 |
|---|---|---|
| requirements 写的是 | `torch==2.14.1` | PyPI 上该版本 Linux x86_64 wheel 为 **554.6 MB**，且 `requires_dist` 含
`nvidia-cudnn-cu13`、`nvidia-cusparselt-cu13`、`nvidia-nccl-cu13`、`nvidia-nvshmem-cu13` 等 **CUDA 依赖** |
| 我本地验证用的是 | 从 `download.pytorch.org/whl/cpu` 装到的 `2.14.1+cpu` | 与上面**不是同一个制品** |

后果：评测机按 requirements 预装时，要么因 554 MB wheel + 数 GB CUDA 依赖超出磁盘/时间限制，
要么在无 CUDA 环境装不上 CUDA 栈，或预装阶段无法取到 CPU 专用轮子 → 依赖安装失败 → 进程以 1 退出。

**这是我这边的实现缺陷**：我验证的是 `+cpu`，交付的却是会把 CUDA 依赖链拉进来的普通 `torch`。

次要缺陷（同样应修）：

1. `rtdl_num_embeddings>=0.0.5` 是范围约束，违反指南"锁定版本"的要求。
2. 包内 `tabm_official.py` 在**模块导入时**就 `import rtdl_num_embeddings`，
   让该依赖成为推理链路的硬前置，任何一个环节装不上都会直接 ImportError → 退出码 1。

## 3. 无法从本地排除的其他可能

- 评测机预装阶段若本身无外网，任何需要下载的依赖都会失败（与哪一版无关）。
- 评测镜像的 Python 若与 3.11 有偏差，cp311 wheel 不匹配。
- 我在本地用平台真实入口跑通过（FINAL_v1：7 个信号日、2,100 行；ALT_v1：同），
  所以**输出格式、池覆盖、时间顺序这些不是本地可复现的失败点**。

### 8.2 本轮新发现并已修的一个真缺陷

首次复跑 TREE_v1 时 `l5_seed20261005` 与随包模型不一致（max abs 3.3e-2、排序不同）：
随包模型用 6 线程训练、`train.py` 默认 8 线程，**LightGBM 跨线程数不保证位一致**。
已把 `train.py` 默认线程固定为 6，重跑后 6 个模型全部差 **0.0**、排序一致。

同类不一致在 `ALT_v1` 上**尚未修**（其 `train.py` 默认 8 线程、随包模型 6 线程）。
当时对 ALT_v1 实测的复现误差只有 ≤5e-11（没触发分歧），但既然同类不一致已在 TREE_v1 上
产生过 3.3e-2 的真实分歧，**若改用 ALT_v1 上传，必须先固定线程数并重验**。
