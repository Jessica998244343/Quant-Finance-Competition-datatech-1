**接收正确重拟合的 TabM 年度产物、当前 C1+TabM 锚点及 2021 静态 CPU 推理证据；不接受“V1 范围内无遗留硬项、比较全部完成”的声明。**

## 4. V1 剩余问题与修正范围

### 4.1 年度夹具覆盖了另一种成员组合

`s6_v1_fixture.py` 实际固定 `SEEDS[0]`，加载一个 `tabm.safetensors`；其参考融合也只读取该 TabM seed 的预测。三个年度通过的是 **C1 三 seed + TabM 单 seed，PyTorch 前向**。当前候选则为 **C1 三 seed + TabM 三 seed，NumPy 前向**。

2021 另有实际 ZIP 全年度验证，本轮也已独立复核，故 2021 候选证据接收。DEV19/20 尚没有当前六成员 NumPy 包的完整年度对照，不能用旧单 seed 夹具替代。

**修正：** 用与现行包同一 scorer、同一构建路径和真实年度三 seed 权重补 DEV19/20 全期对照。保留每个原子 raw 输出、日秩、家族均值、最终输出、池和每日 IC 检查，防止只测最后排序掩盖中间错误。年度期望日期须来自独立合法日历/窗口，不只来自待验收预测自身。全连接验证完整键，禁止内连接漏股后仍报一致。

不需为此重训九个 TabM。原单 seed 夹具保留并明确标注范围。

### 4.2 复现检查跨全年取秩，导致指标错误

`s6_v1_repro_check.py` 把整年 72,900 行一次传给 `Scorer.atom_scores(frame)`、`Scorer.score(frame)`。包 scorer 的 `_rank` 按传入整个 frame 排名，其调用契约是一日；因此这里按全年排名后融合，末尾再按日算 IC，得到另一策略。

这解释了 `v1_repro_check.json` 的 **0.064619124** 与正确逐日锚点 **0.064410371** 不同。两边同样错误仍可比较出 0 差异，不能据此称“实际年度融合完全复现”。权重一致证据不受此指标错误影响。

**修正：** 按日完整池调用 scorer，再拼接预测；复现侧同时对已保存锚点比较。输出逐 seed 原始结果，不将仅含 `c1/tabm` 两个家族均值的字典称为六个原子输出。声明只收单日的 scorer 应拒绝混合日期；增加“另一日期不能改变本日分数”的检查。修正后报告 IC 应与 0.064410371 对齐，误差按冻结容差解释。

### 4.3 manifest 校验仍可在关键条件缺失时通过

主 Agent 用现存 `check()` 对当前 manifest 做纯内存负向检查，以下四种都被 `all_true()` 判通过：

1. `member_hashes={}`；
2. `fusion_graph` 改为带额外家族 rank 的错误描述；
3. 权重改为 `{"unknown": 1.0}`；
4. `cutoff` 改为 `2099-12-31`。

`EXPECTED_SEEDS` 也未参与实际检查。现有三个负例覆盖不完整，且这些问题对应已经发生过的缺成员/图错误/截止混淆，不是无关防御性需求。

**修正：** 严格检查哈希键集合恰好等于全部成员、期望专家与 seed 身份、权重键集合、图结构、配置/特征/design/训练截止一致；将权重文件和原子 manifest 绑定。不能只检查“列出来的 hash 是否正确”。实际产包流程调用该校验，失败须返回非零状态，不能仅写 `passed=false` 后正常退出。

修正并复跑有限负例后再扩大 V2 批量实验。包内静态加载器另复制了一份弱化实现，遗漏研究版已有的完整键/整数 k/shape 检查；统一复用已验收核心，避免研究端严、包内松。无需变更正确前向计算。

### 4.4 训练截止名称错位，不可用旧年度模型冒充新的时间外模型

当前 meta 顶层 `cutoff="2021-12-31"`，而 `train_cutoff_note`、`WINDOW="CONF21"` 和实际标签边界均是 **2020-12-31**。这不是泄漏 2021，而是命名把预测年度和训练截止混淆了。

**立即修正身份：** 明列 `train_label_cutoff=20201231`、`validation_year=2021`、预处理拟合截止。现有包和权重作为 2021 年度夹具冻结归档，不覆盖、不转挂新身份。

**推进安排：** 不为补一行“截至2021”立即给所有候选多训练一轮。在 V2 候选冻结前，按已选训练算法为固定控制和最多两个候选生成真正 `label_end<=20211231` 的模型与预处理；只保存及验证模型身份，不自动计算 2022 外层预测指标。训练入口必须支持“训练并保存、不评价外层”的模式，避免照搬 `train_fold()` 末尾自动计算外层 IC 而提前打开 2022。V3 才按冻结清单统一评价。

这里将 V1 原定截止2021研究包的最终补齐时间明确移至 V2 冻结前；这是主 Agent 的阶段安排调整，不能再称其已经完成。

### 4.5 随包训练代码和依赖仍有未闭合项

**官方材料事实：**《提交指南》第2页要求 `train.py` 完整复现提交模型；第8–9页说明审查覆盖 `inference.py`、`train.py` 及其他随包代码，并禁止“使用 getattr 等方法动态拼接并执行逻辑”。这不是禁止所有属性读取，更不是禁止神经网络/torch。[官方材料](../Source/Submission_Rules.pdf)

实际 ZIP 仍带通用 `tabm_official.py`，训练构建会走 `Activation = getattr(nn, activation)`。推理改用 NumPy 并没有移除这段随包训练架构分派。**项目决定：** 按前任务要求改为显式固定架构与 `nn.ReLU`，保留必要许可与来源；不是再次猜测旧 FINAL 失败根因。保留参数布局、初始化顺序和随机调用语义，证明固定实现与原训练实现的前向/梯度/初始化一致；影响训练行为则另建版本并重做相关复现，不能偷换旧权重的训练配方。

`train_requirements.txt` 固定 `torch==2.14.1+cpu`，但未说明该构建的安装来源或完整安装命令；本次只有训练环境 freeze，没有完整安装过程记录。现存环境与复跑产物支持“本机跑通”，不足以支持“仅凭这份文件即可从空环境复现”。补训练依赖的明确来源、命令及实际输出。网络只用于允许的环境准备，不移入推理。

`V1_run_install.log` 是人工整理的安装摘要，不能称原始 stdout/stderr；可继续保留但标注身份。主 Agent 已独立运行现存无 torch 环境，不要求为重造历史日志再次安装运行环境。未来安装和训练直接捕获原始日志，不追补伪历史证据。

- 报告说“删除/权重比较见 §3”，实际 §3 与 `v1_anchor_analysis.json` 没有这些结果。0.5/0.5 是预设控制，尚不能叫 V1 已搜索出的最佳融合。

**有限补正：** 对已有预测补固定 C1/TabM 粗权重与必要删除比较；对 ResMLP 补相对同一锚点的边际 IC，先找回原始实现/训练证据，缺失则最多重跑原定两 DEV 单 seed 并保存完整产物。只有有边际增益才扩 seed/2021。没有证据不能把该架构判死，也不能把控制任务宣布完成。区间按主任务书重算并归档，禁止调用旧 `metrics.paired_ic_difference` 中会删越界索引、改变抽样长度的实现。

## 5. 后续方向：先主模型，再独立信息，再融合

### 5.1 先一次性补齐 V1，保存两个身份

保留当前默认各0.5组合为 `V1_FIXED_ANCHOR`，不因补测权重更高而改写它。有限粗网格可用 TabM 权重 `{0, 0.25, 0.5, 0.75, 1}`，先登记，只用 DEV 选权重；2021 仅复核冻结选择，不逐点拿来挑最优。若不够达到原任务的差异门槛，继续默认0.5。若换权重，另立 `V1_SELECTED_ANCHOR`，以后所有增益同时给固定和选定锚点。

本补测归 V1 遗留比较，独立登记，不偷偷挤入或重复消耗 V2 的40个最终完整向量预算。修正验收、补齐比较后可自动继续原 V2，无需每个小改动请求批准。正式交付时清楚列出 V1 补正证据与仍待 V2 冻结前完成的截止2021模型。

### 5.2 主模型优先：树控制保持，先完成 TabM 两个有针对性的对照

**分析：** 三 seed 后 TabM 两 DEV 合并与 C1 接近，但融合更高；架构互补优于盲目替换主模型。各 seed 轮数和性能分散，优先检查正则与目标对齐，不以外层分数挑“幸运 seed”。

- 保留 k8/宽128/两层控制；先原任务中的 dropout0.1→0.2 单变量。
- 当前已有正融合证据，允许开启原定 MSE+0.1日内相关项对照；按内部成员分别计算，不直接把 Spearman 的不可导排序硬塞入损失。结构/优化参数其余不变。
- 两项分别单 seed 跑 DEV19/20，评价单体及加入冻结锚点的增量，再按既定门槛扩 seed。不要组合 dropout×loss×宽度×k 做网格。
- C2/C3 先复用合法旧预测，按新图和新锚点评价；不因它们同属 CatBoost 就禁止融合，也不因旧组合有增益直接保留。

### 5.3 金融特征的优先级高于继续扩大通用树库

按原任务书 F1–F3：分段趋势/反转、价量条件关系、隔夜与日内差异及路径持续性。先在冻结 C1 上逐组消融，胜出最多两组移植 TabM。F4 必须先证明合法三表中有行业字段，否则跳过。

理由是增加或更清晰表达现有模型未充分利用的信息；不把代数相关的新列包装成独立 alpha。先验证端点、历史长度、缺失/停牌语义和真实 provider 一致性，再训练。模型没提升和特征实现错是不同结论。

### 5.4 再做 TCN 的有限时间信息实验

按原任务书 W20 + 静态支路，并提供无时间支路的同预算控制。TabM 主要处理当前截面特征，TCN 用有序路径验证是否存在额外信息，因此有明确互补假设。单体分数不是唯一标准，但必须对锚点有可观察边际 IC 才扩 seed/W60。

当前不新增 Transformer、图网络或 XGBoost/RF 全族搜索。近期504日专家仍须满足半年训练起点改善的触发证据；仅凭2021弱不能触发。PairLogit保持低优先级、一个合法对照，不与上述维度组合扩散。

### 5.5 统一融合和时间确认

沿用原任务：新增最多18个配方、最终最多4个专家配方、每配方最多3seed、最终联合融合最多40个不同完整权重向量。先独立验证模型，再以固定图评估边际增量，最终删除消融；不通过额外家族 rank 偷改图，不因为相关性低就自动加入。

保留现行 V1 锚点与可部署 TREE 控制。最终入围最多两个新候选，完成半年训练起点敏感性、截止2021实际权重/预处理和冻结清单后，才执行 V3 的2022一次性确认。随后按冻结算法全量拟合、验收、交主 Agent 审查，用户手动提交。任何新增训练都不自动评价2022。

## 6. 交付节奏与完成判据

不要求每修一个报告字段单独交付，也不要求主 Agent 逐实验批准：

1. **V1 有限补正检查点：** §4.1–4.3 的当前六成员年度入口、逐日复现、manifest 硬校验先完成，报告身份和依赖/随包源码问题同步解决。冻结默认锚点及有限比较结果后进入 V2；不重做未受影响的训练。若修正改变预测或训练算法，独立版本重验后才能扩大。
2. **V2 正式交付：** 主模型对照、特征、TCN及条件分支完成/有证据跳过；给全部实验台账、固定参照、增益/删除/不确定性、最多两候选及截止2021实物冻结清单。新模型可以没有提升，但不得漏做任务后称完成。
3. **V3 正式交付：** 一次性2022结果、冻结算法全量模型、提交包、可复现训练、CPU与源码验收、全部实际风险。未经主 Agent 独立审查不建议上传。

“任务完成”不等于“找到更高分”，也不等于“某个 JSON 中 passed=true”。当前最应保留的是已经验证的 C1/TabM 互补性和可运行 CPU 路线；最应纠正的是用局部/另一对象的检查替代完整候选验收，以及缺项仍宣称全部完成。
