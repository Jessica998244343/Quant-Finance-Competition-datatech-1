### 4.1 TCN训练实现有真实缺陷

`s6_v2_tcn.py` 在内层和外层均先执行 `TCNModel(...)`，**随后**才 `torch.manual_seed(seed)`。参数初始化依赖进程先前的随机状态，外层初始化也会承接内层运行后的状态。新建了模型并不代表已经执行所要求的固定seed从头初始化。

主 Agent 只实例化现有模型、未训练：模拟两个不同前置RNG状态，再照现有顺序设置同一个声明seed，首层权重最大差 **0.166193336**。因此当前TCN/静态/置乱的比较还混入了未经控制的初始化差异。

另外，序列构造只读取20个价格日，首个close-close收益人为缺失，未读第21个前置价格。内存小样例在前收盘确实存在时仍得到首步收益NaN且presence mask=1。本任务要求的是20个一日收益对应最多21个价格点。注意当前卷积末端感受野只有13步，这个首步问题未必影响当前末端输出，不能据此解释已有IC差异；仍需把输入定义和实现对齐，并明确price presence与通道有效性。

### 4.2 TCN产物不足以复算现有结论

训练函数返回预测，`main()` 只把汇总写入 `v2_tcn.json`，没有保存年度权重、预处理/序列统计、曲线或逐日预测。交付目录中也未发现这些产物。当前无法用原预测重算正确融合图或做配对区间。

**修正顺序：** seed必须在每次初始化之前重置；补序列输入和真实provider对照；模型/优化器/RNG重新建立；训练后立即保存完整原子产物，再按原W20和静态控制在两个DEV单seed有限重跑。置乱诊断如继续引用也须以修正版重新产生并保存，不能引用旧结果替代新对照。先修好保存和验收，禁止先补三seed训练、最后再发现无产物可验。

修正后再用原门槛判断是否扩两个seed/2021，W60仍仅在有增量时触发。不以这次审查自动保证TCN晋级，也不自动取消它。

## 5. 系统性问题：新增成员融合重新引入中间排名

`s6_v2_cat_variants.py`、`s6_v2_tabm_variants.py`、`s6_v2_feature_ablation.py`、`s6_v2_tcn.py` 均读取已最终排名的 `v1_anchor__*.parquet`，再与新模型日秩加权。部分V1 ResMLP边际代码也相同。

设每个家族seed日秩均值为q，冻结锚点加权和为：

`u = 0.5*q_C1 + 0.5*q_TabM`。

已约定的三专家扁平图为：

`rank((1-alpha)*u + alpha*q_new)`。

本轮实际为：

`rank((1-alpha)*rank(u) + alpha*q_new)`。

这两者通常不同。后者可以另立嵌套集成算法，但不是本任务冻结的扁平图，不能不改身份就用它筛选、再交扁平包。此前多次提醒过的中间rank问题在新增成员处复发。

主 Agent 对已保存预测按原α=0.10进行只读核验，例如相关损失TabM：

| 窗口 | 本轮嵌套图ΔIC | 约定扁平图ΔIC |
|---|---:|---:|
| DEV19 | +0.000240566 | +0.000266350 |
| DEV20 | −0.000099659 | **+0.000009852** |

这不意味着相关损失已经足够好，而是说明图差异真的会改变结论方向。

**修正：** 全部融合共用一个接收真实原子/家族均值和完整权重向量的实现，输入带图阶段身份，禁止用已经最终排名的父输出替代父加权和。用六成员原子及小型非平凡例子证明包、离线评价、新增成员扫描一致。保留原子完整股票池，禁止内连接掩盖缺股。

先对现有C2/C3、TabM变体、ResMLP预测复算原先登记的α `{0,0.05,0.10,0.25,0.50}`；多个脚本实际只做α=0.10，不能声称已完成整个门槛比较。dropout0.2除替换比较外补第二专家增量，只有既定DEV条件通过才扩2021，不利用2021逐点扫权重。不重训这些已有正确权重来改融合公式。

## 6. 特征阴性结果的有效范围

F1–F3当前数学实现及九天真实输入抽查有支持；但 `s6_v2_feature_ablation.py` 和TCN一样，训练后仅返回预测并最终保存汇总JSON，没有保存模型、完整曲线、逐日预测。因此报告的特征单体数值目前只能记为“汇总观测”，不能独立复算正确图下边际IC、逐日分解和不确定性。

F2在本轮汇总中加入锚点后两DEV均小幅正，单体一正一负；不应仅凭单体回退直接代替融合判断。这里不预判它一定保留，先补可核验产物和正确融合。

执行 Agent 先查是否有未登记的原始权重/预测。能找回则登记真实来源，不能事后伪造旧训练日志。确实未保存则只重跑原定F1/F2/F3的两个DEV单seed，训练结束立即保存；不需要重复训练已自证的BASE，除非改动训练或输入。当前F123三组联合超出了原任务“胜出组、最多一个两组联合”的设计，保留历史记录并计预算，不把它当必做项继续扩训。

原始任务对F2换手、零值/停牌处理等有定义要求，执行 Agent 应把当前确切实现记录为配方，并逐条核对差异；若修改特征定义，另立版本，不能把旧分数转挂。无需重启原始数据审计。

## 7. 冻结与复现记录还不具备 V3 条件

### 7.1 部署汇总被另一种运行结果覆盖

报告指向的 `v2_deploy_models.json` 实际内容是：

`{"deploy": {}, "half_year": {...}}`。

`--deploy` 和 `--halfyear` 使用同一个默认输出路径，每次重新建立空report并覆盖写入，后跑半年任务会清空部署汇总。CatBoost训练函数也未保存完整内层曲线；12个文件中有三份TabM曲线，**没有三份CatBoost曲线或逐原子manifest**。因此“权重/预处理/内层曲线/manifest全部齐备”的范围被夸大。

修正输出为独立run ID和默认拒绝覆盖；恢复可追溯的原始日志/曲线。由现存权重与曲线能重建的树数/epoch信息可以补，但必须标为重建元数据，不能冒充原始训练证明。源代码、输入/特征顺序、合法拟合日期集合、内层/外层标签边界和原子hash需绑定。确有无法补证的部分才有限复跑对应模型，不默认重训全部六个控制。

### 7.2 2022比较对象和决策规则没有闭合

清单中只有V1锚点的C1/TabM六权重，没有实际TREE（L5/C1）截止2021模型；R_DEPLOY仅给旧2019–2021预测路径。决策规则写 `dIC>0`，却未明确该差值相对哪个实际2022控制。无新候选时，不能把V1锚点同时当候选和自身参照，再沿用原“相对V1提升”标准。

重新冻结时须列出确切的候选/固定C1控制/实际TREE结构控制/部署桥接参照、各自截至2021权重及哈希；桥接如无法做成可比的2022模型须提前明确其不可比较范围，不能套用已经训练到2022的旧提交权重做样本外控制。当前C1控制可直接来自已有三份权重。

明确每个ΔIC的分母参照、主候选与备用优先顺序、全年与半年判据、失败如何处理，写定后才看2022。如果修正后仍只有V1，2022任务应明确为“验证V1相对固定控制是否得到时间外支持”，不能伪称“V2新候选超过V1”。

现有 `manifest_hash` 经核验是**去掉该字段后、sort_keys=True且紧凑分隔符的JSON哈希**，不是文件字节哈希；这种定义可以使用，须写明算法，或另存文件SHA-256。不能因它不等于文件hash就认定文件被篡改。当前12个权重/配置文件哈希均匹配，身份校验不等于研究完成。

特征说明 `F0 (33-1)+G1(19)=61` 也应改为实际有序列清单/hash；现有F0为42列，G1为19列。

### 7.3 统计与访问登记

`s6_v1_anchor_compare._interval()` 对合并DEV的487天整体抽块，没有按年分别抽样保留244/243日数，与冻结方案不一致。它已修复旧的缩短样本长度问题，但仍需恢复按年抽样。主 Agent 上轮给出的区间可作为核对基准，不以不同算法算出的区间宣称新增稳健性。对新入围组合重新算，不挪用旧组合的区间。

当前访问登记遗漏V1权重网格在所有权重上计算2021、逐seed删除、V2控制复现及三个半年窗口等访问。代码事实上已计算这些指标，应如实补记；不能只写“2021只看过冻结权重”。2021本来就是已使用的复核年，诚实登记即可，不重称盲集。原始官方分数身份不受这些本地复算影响。

## 8. 接下来怎么推进

按以下依赖顺序执行，仍由执行 Agent 实现，主 Agent 审查；不要求每个小修正单独申请或交付：

1. **先修公共融合与保存机制。** 按原有权重网格复算已有原子预测，修正半年同seed对照及台账，禁止覆盖旧结果。先不打开2022。
2. **开启一个TabM 504日窗口对照。** 这是更正参照后被触发的原条件分支；先两DEV主seed，其余配方固定。单体、加入固定锚点增量和同窗控制都报告。
3. **修TCN并完成W20/静态控制的有效比较。** 初始化和输入契约先验证，立即保存全部产物；以正确图边际IC决定是否扩seed/2021。保留序列作用诊断，不用单体强弱替代互补性。
4. **补特征实验可复核产物和边际比较。** 优先复用，只有确实丢失或特征实现改变才有限重跑；不新增特征组和大型模型族。
5. **对通过者扩seed，完成有限融合和删除消融。** 现有dropout/相关损失/C2/C3也按修正图完成原网格，未过门槛的保留阴性结论。不得为了把报告凑成阳性强留模型。
6. **重新冻结最多两个候选及明确控制，再交审查。** 修复前的2022清单只作历史记录。本次因候选淘汰和参照结论发生反转，执行 Agent 不得凭旧草案自动继续V3；交新的V2修订报告与机器证据，主 Agent核对后才释放2022确认。

预算保持原上限：最多18个新增配方、最终最多4个专家配方、每配方最多3seed、最终联合融合最多40个不同完整向量。修实现的重复运行记录为修正版运行，真实资源和所有尝试仍登记；不得借“修正版”隐藏新的参数搜索。已有F123等越出原设计的探索也须保留记录。

建议下一次集中交付一个 `DS_stage4_V2_REV1_REPORT.md`：先给每条本审查问题的证据和状态，再给正确比较表、哪些旧结论被撤回、有效候选与阴性结果、实际预算、冻结清单。未完成则明写未完成，不再把“有一个汇总JSON”作为完整研究验收。

本次最重要的方向变化是：**TabM近期训练分支应启动；TCN不能以现有理由淘汰；修正融合后才有资格认定V2没有收益。** 保留已经正确的V1锚点与CPU部署成果，将返工限于受影响的比较、训练实现和缺失产物。
