# A 阶段代码复核发现（含实测影响）

每条按「事实 → 实测 → 处理」记录。静态复核发现由主 Agent 交接；此处补充本阶段的量化结果。

| # | 发现 | 实测结果 | 处理 |
|---|---|---|---|
| 1 | 平台 research 数据对 `MarketData`/`Factor33_winsor` 做当日 Barra 成分内连接；`qf3/dataio.py`+`panel.py` 直接切年度并集 | 每个交易日被丢弃的行占 9.2%–14.5%；平台每日恰好 300 行，旧离线窗口约 350 行；差异 120/120 天全部存在 | **确认**。新增 `panel.build_panel(membership_filter=True)`，产出 `panel_platform.parquet`（真实语义缓存） |
| 2 | 旧验收（`acceptance.py::window_for`）也用年度并集，离线与包内一致不能证明与平台一致 | 确认：旧测试两边都无过滤，因此「逐值一致」只证明包与旧面板同源 | 本阶段改用平台语义面板重做比对；旧验收记录降级为「包内一致性」证据，不再当作平台一致性 |
| 3 | `feature_catalog` 把 G1 登记为 `cs_rank`，实现里 G1 是原始值 | 确认。且 `cs_rank_center` 先做 `(rank-mean)/n` 再**按该列最大绝对值重新缩放** | **新发现**：该缩放使列对缺失模式全局敏感。成分过滤只改变 24 只股票的历史，却通过 `dir_x_amt` 把差异扩散到 296/300 只；最大绝对差 0.0120。登记与实现不符已记录；缩放行为在下一版另立实验，不就地改 |
| 4 | CatBoost `get_best_iteration()` 被当作迭代数 | 确认：CatBoost 该值为 0 基索引，代码按迭代数使用，重拟合少 1 棵树（实测模型 `tree_count_=290`） | 记录为 CORR-1。当前 legacy/aligned/包内三处口径一致，不改变本阶段比较；下一版修正时单独登记并重测 |
| 5 | 样本权重归一化依赖未来样本数量 | 确认：`cv.make_target` 用**整个面板**的 `weights[finite].mean()` 归一，而它含未来年份样本。旧窗口上该常数=1.0000，折内均值分别为 1.0315/1.0202 | 记录为 CORR-2（PIT 卫生问题，量级约 2–3% 权重缩放，经正则化产生微小影响）。修正版另建版本，不混入策略增益 |
| 6 | 包内 `train.py` 用 `sys.modules` 注册 + 动态加载 | 确认存在 | 记录为 CORR-3。B/C 的新包改为普通明确导入；旧包不动，只改封装时须证明预测逐值一致 |
| 7 | 「增益远超门槛所以选型偏差可忽略」不是统计结论 | 确认表述过强 | 本阶段报告改为有限结论，列出已使用年份与重复选型限制 |

## 补充事实（本轮新增）

- 旧折模型可用原配方、原种子、原轮数**逐位复现**：重拟合预测与 stage-1 OOF 的最大绝对差为
  `0.0`（LightGBM 与 CatBoost，DEV19/DEV20/CONF21 三个窗口），因此 legacy 三栏证据可信。
- 修复标签口径的一个自身 bug：带成分过滤建面板时，早期实现会让标签端点也被过滤，
  导致合法标签比例从 98.07% 掉到 97.94%。已修正为「标签始终从不过滤的 MarketData 构建」，
  修正后两套面板的标签值与缺失掩码完全一致（最大差 0.0）。
